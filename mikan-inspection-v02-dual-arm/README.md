# MIKAN LAB v0.2 — 2本アーム比較版

公開先: https://ykoba079.github.io/test_prj/mikan-inspection-v02-dual-arm/

[1本版](../mikan-inspection-v02/)を残し、ラインの反対側に2本目のアームと専用の不良品籠を追加した比較用デモです。1本版のアーム制御コードや吸着条件は変更していません。

## 比較すること

- 片方が把持・搬送・戻り中でも、もう片方が別のNG個体を処理できます。
- 右上にARM A / ARM Bの回収数・試行数・失敗数を表示します。全体の検出数・回収数・取り逃がし数も表示します。
- 対象個体を予約して、2本が同時に同じミカンを取ることを防ぎます。割り当て順は交互に切り替えます。
- NG確定後の内部座標による追従、Havokの吸盤接触・負圧・持ち上げ確認を使います。果実をアームへ親子付けして運ぶ方式ではありません。
- 取り損ねた個体は、担当アームが戻った後に予約を解放します。範囲内であればどちらかのアームが再試行でき、同一個体の試行は合計最大2回です。

アームAの基部は `(3, 0.9, 2.1)`、Bは `(3, 0.9, -2.1)` です。Bは元の関節計算を180度回転した座標系で使い、見た目・工具位置・Havokの吸盤・箱の開放位置を同じ世界座標に合わせています。ARM Bの不良品籠は反対側に置き、両方とも1本版と同じ規格サイズです。未判定回収を有効にした場合は各側の青い籠も表示します。

## 共通条件

カメラ2台の位置・投影、YOLOv9-Tの重み、入力解像度、信頼度35％、別撮影2回の確定条件、投入間隔2.5秒、ミカンの外観・サイズ、ローラーの初期値、吸着圧78kPaは1本版と共通です。2本のアームは両カメラの画像にも描画されるため、設備による遮蔽が増える場合も含めて比較します。

初期の果実と自動投入の乱数シードは共通ですが、実行速度や物理演算・推論のタイミングによって結果は変わります。2本化で回収率が必ず上がるという結果を保証するデモではありません。

## 残している課題

1本版で確認できる搬送中の吸着外れ・落下は、2本版にも残しています。吸着条件や速度を変えて成功扱いにせず、失敗として集計します。アーム同士の本格的な衝突回避や経路計画は実装していません。リンクの見た目の交差、吸盤やミカンの物理接触、設備による遮蔽を観察する段階です。

## 構成と確認

このフォルダーには比較版の画面・協調制御・配置変換を置き、BabylonJS、Havok、YOLOモデル、果実・設備などの共通資材は `../mikan-inspection-v02/` と `../yolo-camera/` を参照します。リポジトリーのルートでHTTPサーバーを起動して開いてください。

```powershell
python -m http.server 8000
# http://localhost:8000/mikan-inspection-v02-dual-arm/
```

`node mikan-inspection-v02-dual-arm/test-dual-arm.cjs` で、2本の世界座標と独立した吸盤、両カメラへの描画、実際のYOLO推論、別個体の同時処理、両吸盤での物理接触と負圧、試行の終了と取り逃がし集計、箱への工具到達・箱の物理形状、PC・スマホの表示を確認します。スケジューラー検証では画像検出を注入し、吸着外れも結果に残します。検出精度と回収率を統計的に評価する試験ではありません。

履歴のJSONには `robots` と試行ごとの `armId` を追加しています。
