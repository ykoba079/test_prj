# MIKAN LAB V0.2：回転・多視点検査

YOLOv9による画像検出と、Havokによるローラー搬送を接続した検査ラインのデモです。サンプル一覧にはV0.2のみを掲載し、旧版のファイルは保管用に残しています。

## 2026-10-25：YOLOv9を接続

標準の検出器を、学習済みのYOLOv9-T改善モデル（入力640）に変更しました。真上・斜め上のカメラ画像から `mikan`（果実全体）、`mold`（カビ部分）、`damage`（傷部分）をONNX Runtime WebのWASMで推論します。不良部分の中心が果実枠内にあり、面積の60%以上が果実枠と重なる場合、その果実へ対応付けます。対応先のない不良枠は紫で表示し、個体の排除判定には使いません。

同じ個体で2つの別撮影フレームに不良を検出すると、履歴に保持し、出口でアームが赤い箱へ移します。生成時の正解種別を判定へ渡していません。検出方式で従来の色解析も選択できます。方式やYOLO信頼度を変えると、ラインと履歴をリセットします。JSONには検出器、閾値、クラス別最大スコアを保存します。

モデルは `models/quality-640/` に同梱しています。合成画像50枚（学習35・検証8・旧テスト7）を使用し、検証結果でモデルを選択してから、新規33枚で評価しました。新規画像のカビは9/10、傷は10/10がIoU 0.5以上で一致しました（信頼度0.25）。カビの見逃し1件、カビの余分な検出1件、果実の余分な検出1件が残ります。回転動画や実物での検出精度を示す値ではありません。モデルの由来・設定は `export-report.json` を参照してください。

端末の処理速度によって観測回数が減るため、初期ローラー速度を8 rad/sにしています。観測不足の個体は青い箱へ隔離します。最初から途中に置かれた見本も観測不足になり得ます。入口から手動投入して一周の流れを確認できます。

モデル読込中は静止した3Dを表示し、失敗時はエラーを表示して停止します。色解析へ自動変更しません。エラー画面のリンク、または `?detector=color` で色解析デモを明示的に開けます。

## 起動と公開URL

リポジトリーのルートで `python -m http.server 8000` を実行し、http://localhost:8000/mikan-inspection-v02/ を開きます。

GitHub Pagesの公開先： https://ykoba079.github.io/test_prj/mikan-inspection-v02/

BabylonJSとHavok（JavaScript / WASM）は `vendor/`、ONNX Runtime Webは共用の `../yolo-camera/vendor/` から取得します。モデルを含め同じオリジンから読み込み、外部CDNへの接続は不要です。フォルダー単独ではなくリポジトリーのルートをHTTPで配信してください。`.mjs` はJavaScriptのMIMEタイプで配信します。

## 2026-10-25：青緑色のカビ表現

カビの表面表現を、青緑色の広い斑点・薄い白色の縁・粉状の細かなムラに変更しました。色合いの参考は[伊藤農園の写真](https://www.ito-noen.com/dictionary/tips/826/)です。模様自体はコードで手続き生成しています。

斑点のメッシュを球面に沿って細分化し、果実表面の下に沈んで模様が途切れる問題も修正しました。比較用の色解析デモも青緑色を検出するよう調整しています。

## 2026-10-08：空白表示の対策

Havokの初期化を待つ間も、ミカンと装置の静止した3D表示を開始します。初期化に失敗した場合も静止表示を残し、読込エラーを画面に表示します。静止表示を物理搬送として扱う自動切替はありません。初期化中・失敗時の投入や制御は無効です。

ライブラリーを同梱して外部CDN依存を撤去し、アプリとモジュールのURLに更新識別子を付けて、新旧キャッシュの混在を防止しています。WASM取得は20秒でタイムアウトします。

`node mikan-inspection-v02/test-startup.cjs` で、WASMの読込を遅延させた場合の先行描画、外部CDNを遮断した状態での正常起動、WASM取得失敗時の静止表示とエラー表示を検証します。

## 2026-10-08：Havokによるローラー搬送

従来のミカン位置・回転角の直接更新を廃止しました。固定軸のローラーはANIMATEDボディの円柱とし、モーター相当の角速度を与えます。ミカンは扁球の凸包を形状とするDYNAMICボディです。重力・接触・摩擦・慣性・果実同士の衝突によって移動と回転が決まります。搬送中のミカンには並進速度、角速度、前進の力を直接与えていません。

物理サブステップは1/120秒、果実質量は0.18、重力は9.81、反発は0.02です。寸法はデモのワールド単位で、実機の寸法・材料・実測運動に合わせた校正は行っていません。皮の変形は扱わない剛体モデルです。

投入は入口が空いたときに行い、重力でローラー上に落とします。側面レールも物理ボディで、横方向の転がりを制限します。落下・ライン外への逸脱は別カウントとして記録します。

選別中はローラーモーターを止めますが、他の果実は慣性で動けます。アームが把持した果実だけ物理ボディを外し、従来の制御アニメーションで箱へ移します。

## この版でできること

- モーター駆動ローラーとの接触・摩擦による搬送と果実の回転。
- ローラー角速度、ミカンの摩擦係数、不良投入率の変更。
- モーター停止（物理演算は継続）と一時停止（物理演算も停止）。
- ミカンの速度・角速度・接触イベント数と落下数の表示。
- 表面に固定した不規則なカビ・擦り傷、皮の細かな模様と凹凸。
- 真上 / 斜め上の2台のカメラで640×320のレンダー画像を取得。
- 両画像をYOLOv9で解析し、ミカン位置と見えている不良を検出。比較用の色解析にも切替可能。
- 画像座標を果実中心の高さの平面へ逆投影し、撮影時の個体位置と対応付け。
- 同じ個体の複数フレームの判定を統合。2つの別フレームで不良を検出すると確定し、その後隠れても保持。
- 観測方向とフレーム数による、良品 / 不良 / 未判定の区別。
- 不良は赤い箱、未判定は青い箱へアームで移動。良品は直進。排除中はモーターを待機させます。
- 個体別履歴の表示とJSONダウンロード（最新80個体まで、画面は最新14個体）。
- 良品、カビ、傷、裏面カビの手動投入。自動投入も停止できます。

## 摩擦・モーターの比較

1. 自動投入をオフにし、リセットします。
2. 摩擦係数を0にして「良品を投入」。ローラーは回転してもミカンはほぼその場に残ります。0の比較ではローラー側の摩擦も0にしています。
3. 摩擦を0.7に戻し、リセットして「裏面にカビを投入」。接触によって進みながら回転し、底面カビが見える向きになると検査画像から検出されます。
4. 「モーター停止」でローラーを止めても、ミカンには慣性・重力が作用し続けます。
5. 「一時停止」では位置と姿勢も停止します。再開するとその時点の状態から物理演算を再開します。

果実の回転速度と搬送速度を別々に指定する旧コントロールは撤去しました。物理的な回転が十分な観測方向を得られなかった場合は、検査区間出口で未判定として青い箱へ隔離します。

## 判定の意味と制限

生成時の不良種別は外観作成のみに使い、画像検出・選別判定に渡していません。「不良未検出」は正常品であることの保証ではありません。

皮・カビ・傷は手続き生成した教材用表現です。YOLOのスコアはモデル出力で、品質の保証確率ではありません。色解析モードはAIを使用しません。実物の品質判定には実写データによる学習と評価が必要です。

観測方向は、撮影時のカメラ視線を果実の局所座標に変換し、球面上の12方向のうち最も近い方向を記録します。同じ撮影時点の2カメラは、観測方向は各々記録し、フレーム数と不良確認回数は1回として数えます。

「観測十分」の基準は12フレーム以上・8方向以上です。これはデモの判定ルールであり、表面の検査済み面積・全面検査・実物の良品保証を意味しません。基準を満たしても不良を見逃す可能性があります。

ID対応付けは、撮影時の既知の3D個体位置との最近傍照合です。実画像だけを使った追跡ではありません。入口の空きを確認して投入しますが、物理演算で果実同士が接触・重なって見える場合があります。

ローラー駆動と果実の運動はHavokで計算します。アーム、逆運動学、実機制御は物理化していません。二軸回転を直接指定する機能も撤去しています。

## 検出器の接続箇所

`vision.js` の検出器インターフェースは `detect(ImageData)` → `[{ x0, y0, x1, y1, defects: ['mold', 'damage'] }]` です。アーム・個体履歴・観測方向は検出器と分離されています。

`yolo-detector.js` がミカン全体と不良部分のモデル出力をこの形式へ変換します。V0.1の `good/mold/damage` 全体枠方式のモデルとはラベル設計が異なります。

## 検証

`node mikan-inspection-v02/test-yolo-browser.cjs` は実際のYOLO推論、カビ・傷の確認とアーム排除、方式切替、信頼度変更、JSON、モデル読込失敗時の停止を確認します。

`node mikan-inspection-v02/test-browser.cjs` は比較用の色解析モードで、実際のEdge / WebGL描画に対して以下を確認します。Playwrightのインストールパスは環境に合わせて変更してください。

- 摩擦0ではほぼ搬送されず、摩擦ありでは接触により前進・回転すること。
- ローラーはANIMATED、果実はDYNAMICとして計算されること。
- 物理的な回転により底面カビが画像で検出されること。
- カビ・傷のアーム排除、観測十分な良品の通過、観測不足個体の隔離。
- 一時停止で位置・姿勢・観測フレームが固定され、モーター停止では物理演算が継続すること。
- リセットで果実の物理ボディを解放し、ボディ数が初期値に戻ること。
- 履歴JSON、スマホ幅の表示、JavaScriptエラーがないこと。

公開先の検証には `MIKAN_TEST_URL` 環境変数を設定します。色解析の回帰試験ではURL末尾に `?detector=color` を付けます。

物理APIの公式資料：[Physics V2のボディ・形状・摩擦](https://github.com/BabylonJS/Documentation/blob/master/content/features/featuresDeepDive/physics/v2/rigidBodies.md)。
