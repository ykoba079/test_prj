# MIKAN LAB v0.2

BabylonJS / Havok / YOLOv9-Tによるミカンの搬送・画像検査・ロボット選別デモです。
公開先: https://ykoba079.github.io/test_prj/mikan-inspection-v02/

リポジトリーのルートで `python -m http.server 8000` を実行し、`http://localhost:8000/mikan-inspection-v02/` を開きます。BabylonJS/Havokは `vendor/`、ONNX Runtime Webは `../yolo-camera/vendor/` を利用します。`.mjs` をJavaScriptとして配信するHTTPサーバーが必要です。外部CDN接続は不要です。

## 箱と操作

- 箱へ入ったミカンは時間経過で削除しません。深くした半透明の箱に物理ボディを持ったまま残ります。
- 「箱を空にする」で回収済みだけを削除します。角度変更ではライン・箱・履歴をすべて初期化します。
- 検出方式・信頼度の変更時はラインと追跡を初期化し、箱の中身を保持します。
- ライン上の上限14個に箱の中身を含めません。長時間運転では物理ボディが増えるため適宜箱を空にしてください。
- 初期ローラー速度は8 rad/s、投入間隔は8秒です。ローラー速度は従来値へ戻しています。どちらも変更できます。速度を上げると取り逃がしが増えることがあります。
- 先端は真空吸着パッドです。「吸着の負圧」は初期60 kPa、「空気漏れ」は初期0%です。運搬中に負圧を下げたり漏れを増やしたりすると、保持力低下と落下を試せます。圧力・力は模式モデルの値です。
- 起動・設定変更時の初期3個は、正常・カビ・傷の動作確認用です。不良面を上向きに投入します。自動投入・追加投入は従来どおりランダムな面、「裏面にカビ」は裏向きです。アームの制御が正解姿勢を参照することはありません。
- 未判定回収は初期状態では無効です。画像で不良が確定した対象にアームを使います。未判定回収を有効にすると、未判定の対象も青い箱へ回収します。
- ライン終端へ到達したミカンは緑の箱へ落下します。合格判定を保証するものではありません。「未判定通過」「取り逃がし」を別に表示します。

## カメラ・検出・追跡

真上Aと約45度の斜めBから640×480画像を取得します。Aは従来の平行投影を維持し、Bは透視投影です。Bは筐体位置（1.2, 2.8, 2.4）から中心（1.2, 0.35, 0）を見下ろし、垂直画角65度・画像比4:3を固定しています。手前と奥で果実の見かけの大きさが変わります。果実サイズの確認には、検出枠の中心から基準面（y=0.35）へ逆投影した位置で想定直径0.78を再投影した画素幅を使います。個体の正解位置を参照せず、基準面と異なる高さでは誤差が残ります。実カメラではなく同じ3Dシーンの仮想カメラ描画で、描画画像をYOLOへ渡します。Bは画面表示だけを上下反転し、検出枠とT番号も同じ反転位置へ描きます。文字は正立のままです。推論と位置変換は元のカメラ座標で行います。果実・ローラー・回転マーカー・側壁・床・箱・アーム・周辺設備を同じシーンから描画し、設備による遮蔽や背景の模様も含めて推論します。自身の筐体模型が光路を塞がないよう、そのカメラ自身の筐体模型だけは描画から外します。他の設備は通常の深度判定で隠れます。目標位置のデバッグ球は検査画像に含めません。実機背景での精度は別途検証が必要です。撮影範囲はx=-1.2〜3.6、把持区間はx=1.55〜3.25です。A/Bを毎回撮影し、2つのWeb Workerで並列推論します。初回推論の準備は起動時に行います。推論中もHavok・描画・搬送・アームは動き続けます。遅い端末では古い画像による把持を見送ります。

モデルは `mikan`（果実全体）、`mold`、`damage` を検出します。不良部分の中心が果実枠内にあり、その60%以上が果実枠と重なる場合に関連付けます。果実枠は信頼度65%以上に加え、サイズ・形・画像内の果皮色の支持率20%以上を確認します。真上の位置更新は、果皮・青緑色の画素範囲が想定直径の幅85%・高さ70%以上残る場合に限定し、その中心で位置を補正します。色は背景の誤検出除去と位置補助に使い、カビ・傷の分類はYOLOが行います。不良部分の閾値は画面のスライダーで指定します。

位置・速度・追跡IDはAの画像検出だけから作ります。Bは一意に対応した果実へ不良の証拠を追加し、位置や速度を上書きしません。Aで隠れた対象の存在を補助確認する場合も、位置推定には混ぜません。別々の撮影2回、または3回以上追跡した果実で信頼度95%以上の不良を1回検出すると確定し、その後隠れても記憶します。同時刻の複数カメラを2回とは数えません。

直近3回までの位置を回帰して速度と誤差を推定します。少なくとも3回の位置観測と安定した推定が必要です。新しい画像に対象がない、対応が曖昧、画像が古い、位置予測の誤差が大きい場合は把持を始めません。

## ロボットと物理

アームは固定長の上腕2.0・前腕1.9、台座(3,0.9,2.1)、工具オフセット0.22です。リンクは伸縮せず、逆運動学と関節速度・加速度制限で動きます。台座±160度、肩-20〜135度、肘12〜150度。最大速度115/85/115度毎秒、最大加速度250/200/260度毎秒平方です。

待機位置を把持区間へ近づけ、不良が確定した対象へ早めに上方から準備します。実際と同じ関節制御を使い、加速・減速・位置合わせを含む到着時間を計算します。上からパッドを近づけ、Havokで接触した位置で工具を止めて真空を立ち上げます。想定高さで接触しなければ、最大0.08だけ低速で探ります。開始には撮影から1.3秒以内の観測が必要です。接近中の遮蔽には、誤差の条件を満たす場合に限り最大3.5秒まで直近の画像から予測します。移動する対象への追従には0.22秒先の予測を使います。搬送や推論は停止せず、吸着後のアームだけは速度を通常の0.65倍として穏やかに運びます。

`tracking.js` と `pick-planning.js` は画像由来の観測だけを受け取ります。生成時の果実ID・正解種別・実位置・姿勢を使って目標を補正しません。吸着判定は `vacuum-physics.js` のHavok接触イベント、負圧の立ち上がり、実際の持ち上がりを使います。果実との距離だけで吸着成功にはしません。

先端の大きな指は取り外し、半径0.16の小さなパッドと空気ホースを表示します。パッド自体もDYNAMICで、工具のANIMATEDボディへ[6自由度制約](https://doc.babylonjs.com/features/featuresDeepDive/physics/constraints/)で取り付けています。上下0.08の逃げと最大力3の押し付けモーターを持ち、接触時に果実へ強制的に食い込ませることを避けます。実際のシール形状は薄い円柱、見た目は柔らかいベローズ状の吸盤です。寸法はシーン内の単位です。

接触法線とパッド内の接触位置から密着度を近似し、真空弁がONのときだけ負圧を立ち上げます。接触なしでは負圧も吸着成功も発生しません。負圧12 kPa以上が0.10秒続くと試し持ち上げを行い、密着が維持され、果実が0.12以上持ち上がって初めて保持を確定します。

保持力上限は「圧力差×仮定した有効面積200 mm²」です。接触点へばね・減衰による力を加え、その大きさを保持力上限で制限します。横ずれに対する力と傾きを戻すモーメントにも圧力に応じた上限を設けます。力と反力は1/120秒ごとにHavokの果実・パッドへインパルスとして加えます。果実は同じDYNAMICボディのままで、重力・接触・落下を継続します。果実を工具へ固定する制約、座標の書き換え、親子付けは行いません。負圧不足、隙間の拡大、過度の傾きで密着が失われた場合は落下し、失敗として記録します。箱の上では真空を解除し、元のボディをそのまま落下させます。

これは空気の流れや実際の吸盤変形を解くCFDではありません。気密性は接触姿勢と漏れ設定による近似で、カビ・傷の見た目から皮の通気性を自動推定するものでもありません。モデルの有効面積・寸法・力は実機校正値ではなく、果実の潰れや皮の破損も扱いません。

Havokの固定軸ローラーをANIMATED、凸形状のミカンをDYNAMICとして計算します。果実へ前進速度や回転速度を直接与えず、接触と摩擦で搬送・回転させます。重力9.81、質量0.18、反発0.02、サブステップ1/120秒です。モーター停止は慣性を残し、一時停止は物理と追跡時計を止めます。アーム手前までの区間（中心x=-2.0〜2.2）を14本（従来7本）に広げ、隣接ローラーを交互に低速側−22.5%・高速側＋10%で駆動する小規模試験を追加しました。基準8 rad/sのとき6.2 / 8.8 rad/sで、区間外は8 rad/sです。最後の速度変更ローラー中心はx=2.19で、標準の把持待機位置x=2.3の手前です。画面で低速側の減速率（−100〜100%）と高速側の増速率（0〜100%）を別々に変更できます。100%減速は低速側を停止、100%増速は高速側を基準の2倍にします。両方0%で等速に戻せます。青が低速、黄が高速です。果実の回転を直接設定することはありません。速度差による回転改善や全面観察は保証せず、裏面カビの露出と搬送を比較します。3台目Cは筐体・撮影・推論・画面から取り外しました。上側の接触ローラーも試しましたが、滞留・追跡の取り違えが増えたため公開版には含めていません。

JSON出力には観測・判定・吸着試行・中止理由・密着度・吸着時の負圧・保持力上限・持ち上がった量・関節制限・箱内個数・設定を含めます。画像追跡IDと生成時IDの対応表は作りません。

## モデルと限界

`models/quality-640/` は合成画像50枚（学習35・検証8・旧テスト7）から学習したYOLOv9-Tです。モデル選択後の新規静止画33枚では、IoU 0.5・信頼度0.25でカビ9/10、傷10/10でした。カビの見逃しと余分な検出が各1件、果実の余分な検出1件がありました。これは回転動画の精度ではありません。今回の制御修正でモデルの再学習は行っていません。

回転中に不良面が十分見えない、撮影間隔の間に通過する、モデルが見逃す場合があります。正常果実のヘタの誤検出も残ります。制御の修正だけで誤検出・見逃しをすべて解消するものではありません。実運転のカメラ画像と回転中の難しい面を追加学習し、動画単位で検証する必要があります。

YOLOから色解析への自動切替はありません。色解析は画面で選択するか `?detector=color` で起動します。初期化失敗時は静止プレビューとエラーを表示します。果皮・カビ・傷は手続き生成した教材用表現です。青緑色のカビは[伊藤農園の写真](https://www.ito-noen.com/dictionary/tips/826/)を参考にしています。モデルの由来・ライセンスは同梱ファイルを参照してください。

## 転がり比較試験（2026-10-28）

初期設定は「改善試験：4項目を適用」です。軸位置は固定したまま、Havokの剛体接触で動かします。弾性変形や接触面の潰れを解くモデルは追加していません。

| 設定 | 凸形状の分割数 | 角減衰 | 加減速上限 | 果実/ローラーの動摩擦 | 静摩擦 |
|---|---:|---:|---:|---|---|
| 従来 | 12 | 0.12 | 即時 | 0.7 / 0.9 | 動摩擦と同じ |
| 摩擦のみ | 12 | 0.12 | 即時 | 1.0 / 1.0 | 1.2 / 1.2 |
| 当たり判定のみ | 32 | 0.12 | 即時 | 0.7 / 0.9 | 動摩擦と同じ |
| 加減速のみ | 12 | 0.12 | 6 rad/s² | 0.7 / 0.9 | 動摩擦と同じ |
| 角減衰のみ | 12 | 0.02 | 即時 | 0.7 / 0.9 | 動摩擦と同じ |
| 4項目 | 32 | 0.02 | 6 rad/s² | 1.0 / 1.0 | 1.2 / 1.2 |

どの設定も摩擦合成はMINIMUMを明示し、材質オブジェクトを形状へ再設定します。摩擦スライダーは果実の動摩擦を変更し、摩擦変更を含む設定ではローラー側も同じ値、静摩擦はその1.2倍です。それ以外では従来のローラー0.9を保ちます。摩擦0では両側の静・動摩擦を0にします。物理エンジンから読み戻した静・動摩擦を表示し、JSON履歴にも保存します。値は比較用の仮定で実機の校正値ではありません。

設定変更はラインと追跡を初期化して初期サンプルを投入し、箱の中身を保持します。箱の既存ボディは当たり判定と角減衰を保ちます（同じ共有材質の摩擦変更は影響し得ます）。32分割でも直径0.78、扁平率0.84、質量0.18は同じです。緩やかな加減速は1/120秒の物理ステップごとに適用され、モーター停止も減速して止まります。速度差100%の目標は基準8で0 / 16 rad/sのままです。

「接点滑り」は、衝突点での両物体の速度（並進＋角速度×接点までのベクトル）の差から、法線方向を除いた接線速度です。直近0.035秒の接触イベントで観測した値を平均します。接触がなければ数値を表示しません。これはシミュレーター側の診断であり、YOLOやアームの位置推定には渡しません。角速度の積算は往復や回転軸の変化も含むため、全面を観察できた割合ではありません。

`node mikan-inspection-v02/test-rolling.cjs` は6設定を同じ投入位置・4秒の物理時間で比較し、材質の読み戻し、実際の角減衰、接点滑り、前進量、回転、100%目標、加減速上限を記録します。結果は `qa/rolling-comparison.json` です。単一条件の試行であり、設定の優劣を統計的に保証しません。滞留や後退も記録します。`test-roller-trial.cjs --report-only` は前進不足を評価結果として残すモードで、通常モードは前進量の条件を引き続き要求します。

## ライン傾斜の比較（0度・2度・5度）

「ゴール側への傾斜」で切り替えます。初期値は0度です。角度変更ではライン・箱・履歴を初期化し、初期3個を投入します。摩擦比較設定の変更とは異なり、角度変更時は箱の内容も消去します。

標準把持位置x=2.3の高さを支点として、世界のZ軸周りにゴール側を下げます。全ローラーの軸中心・側壁・背景板・検査区間表示を同じ剛体変換で移動し、Havokのローラーと静的コライダーも一度同期します。ローラーの軸位置を搬送方向に走らせる機構ではありません。良品の籠は出口に合わせて水平を保ったまま移動し、床と脚の高さも合わせます。不良・未判定の箱とロボット基部は固定します。

回転変換前の果実中心基準面y=0.35を傾けた平面へ画像の光線を交差させます。果実幅の再投影も斜面方向に沿わせ、T番号の表示位置とアームの目標高さへ同じ幾何を使います。傾斜幾何は既知の装置校正値であり、個々の果実の正解位置は参照しません。実際の果実中心は姿勢や接触で上下するため、基準面による誤差は残ります。吸盤は従来どおり鉛直で、傾斜に合わせた工具姿勢制御は追加していません。
