# MIKAN LAB v0.2 — 画像追跡による選別

BabylonJSで表示し、Havokの接触・摩擦でミカンを搬送・回転させるデモです。YOLOv9-Tの画像検出、画像追跡、位置予測、アームの把持結果を確認できます。

公開先：https://ykoba079.github.io/test_prj/mikan-inspection-v02/

リポジトリーのルートで `python -m http.server 8000` を実行し、`http://localhost:8000/mikan-inspection-v02/` を開いてください。BabylonJS/Havokは `vendor/`、ONNX Runtime Webは `../yolo-camera/vendor/` を共用します。`.mjs` をJavaScriptとして配信するHTTPサーバーが必要です。外部CDNへの接続は不要です。

## カメラとアーム

- 真上・斜め上の2台で640×320画像を取得します。真上カメラの範囲は x=-4〜4、把持区間は x=1.55〜3.25 で、撮影範囲内に把持区間があります。淡緑色のレールが把持区間です。
- YOLOは `mikan`（果実全体）、`mold`（カビ部分）、`damage`（傷部分）を検出します。初期閾値は0.25。カビ・傷の中心が果実枠に入り、部分枠の60%以上が果実枠と重なる場合、その果実へ関連付けます。
- 検出枠の中心を、カメラの校正行列で高さ y=0.35 の平面へ逆投影します。周辺の部分切れやレール外を除き、中心 x=-3.55〜3.55、z=±1.35 内の観測を利用します。
- `tracking.js` は画像由来の x,z、検出種別、スコア、撮影時刻のみを受け取ります。生成時ID、正解種別、実際の個体位置・姿勢は渡しません。T1などの追跡IDは画像検出から新たに付けます。
- 同じ撮影時刻の2カメラを近接位置で統合し、不良は別の撮影タイミングで合計2回検出して確定します。その後カビが隠れても記憶します。対応が曖昧な場合は把持しません。
- 位置の時系列から平滑化した速度を推定し、撮影・推論の遅れとアーム接近時間0.5秒を含めた把持位置を予測します。最新観測が1.8秒より古い場合は把持しません。追跡開始には2回の位置観測が必要です。
- アーム接近中も画像で追跡を更新します。真上カメラの結果が返った時点で反映し、斜めカメラの結果を待ちません。後から同じ撮影時刻の結果が届いても観測回数・不良確認回数は重複加算しません。古い観測、予測点の区間外への移動、空振りは失敗として記録します。ローラー、他の果実、自動投入、検査は待機しません。

## シミュレーターの正解情報を使う範囲

`scan()` と `plan()` はミカンの実位置を読みません。アームは追跡IDを3D個体IDに変換する処理も持ちません。目標は画像から決まります。把持中の果実の再検出は、撮影時の既知のグリッパー位置を各カメラの画像へ投影して除外します。位置の関連付け用の追跡履歴は5秒まで保持しますが、1.8秒より古い観測では把持を開始・継続しません。

把持点へ到着した時だけ、`contactAt()` がその空間に果実があるかを判定します。横方向0.3以内・高さ差0.24以内を簡易接触条件とし、接触した果実だけ物理ボディを外して箱へ運びます。空の場合は空振りで、実位置へ自動補正しません。この接触判定と物理的な搬送・落下・削除には仮想空間の位置を使います。

接触条件、可変長アームの描画、箱への搬送は簡略モデルです。関節制約・逆運動学・接触力・吸着・実機通信は実装していません。実機ではカメラ校正、把持確認センサー、ロボット制御との接続が必要です。

## 判定・表示・記録

不良が確定した追跡は不良箱へ、判定材料が不足する追跡は未判定箱へ把持を試みます。12回以上の撮影観測があり、不良の検出履歴が一度もない追跡は「不良未検出」として通過扱いにします。画像だけでは果皮が何面回ったか分からないため、以前の「仮想姿勢に基づく8方向以上」という判定は撤去しました。

画面のT番号・履歴・不良未検出数・取り逃がし数は画像追跡単位です。追跡の取り違え・断絶があるため、実際の果実数と一致する保証はありません。未排除の実個体通過・物理落下は別集計です。追跡失効、曖昧な対応、区間通過、空振りは理由を記録します。

JSONには画像追跡記録と、把持試行の追跡ID・撮影時刻・推定速度・目標位置・接触時刻・成功/失敗・接触誤差を保存します。実際の果実と生成IDによる追跡対応表は作りません。

## 推論と操作

YOLOの前処理・WASM推論・出力の復元は `yolo-worker.js` で実行し、3D描画をブロックしません。検査画像は推論完了時に更新され、3Dとは更新頻度が異なります。推論中のフレームをキューにためません。端末が遅い場合、古い観測として把持を見送ることがあります。

検出方式で色解析デモにも切り替えられます。`?detector=color` でも起動可能です。方式・信頼度変更時はラインと追跡履歴をリセットします。「モーター停止」は惰性を残し、「一時停止」は物理演算と追跡時計も停止します。初期化中・失敗時は3D静止表示を残し、エラーを表示します。YOLOから色解析への自動切替はありません。

## モデル・外観・限界

`models/quality-640/` のYOLOv9-T改善モデルは合成画像50枚（学習35・検証8・旧テスト7）から作成しています。モデル選択後の新規静止画33枚では、IoU 0.5・信頼度0.25でカビ9/10、傷10/10が一致しました。カビの見逃し1件・余分な検出1件、果実の余分な検出1件が残ります。回転動画、今回広げた撮影範囲、実物での精度を示す値ではありません。由来は `export-report.json`、ライセンスは同梱ファイルを参照してください。

皮・カビ・傷は手続き生成した教材用表現です。青緑色のカビの色合いは[伊藤農園の写真](https://www.ito-noen.com/dictionary/tips/826/)を参考にしています。YOLOの信頼度は品質の保証確率ではありません。

Havokは固定軸ローラーをANIMATED、扁球の凸包を持つ果実をDYNAMICとして計算します。果実に前進速度・回転速度を直接与えません。重力9.81、質量0.18、反発0.02、サブステップ1/120秒で、実機への校正はしていません。

## 検証

- `node mikan-inspection-v02/test-tracking.cjs`：画像だけのID生成、2カメラ統合、2回の不良確認、速度予測、古い観測と曖昧な対応の棄却、接近中の更新、失敗後の自動再試行抑止。
- `node mikan-inspection-v02/test-image-control.cjs`：実際のYOLO画像から追跡・把持・不良排除、誤った観測位置による空振り、追跡失効、搬送継続、JSON、スマホ幅。`--color` で色解析でも確認します。
- `node mikan-inspection-v02/test-yolo-browser.cjs`：実画像のカビ・傷検出、Worker推論中の描画継続、方式・信頼度変更時の履歴破棄、読込失敗時の静止表示。
- `node mikan-inspection-v02/test-browser.cjs`：Havokの重力・接触・摩擦による搬送・回転、一時停止、モーター停止、物理ボディの解放。
- `node mikan-inspection-v02/test-startup.cjs`：WASM遅延中の先行表示、同一オリジンからの起動、読込失敗の表示。

ブラウザーテストはEdge/Playwrightを使います。公開先の確認には `MIKAN_TEST_URL` を指定します。静止した不良面をカメラへ向ける接続試験は、自然な回転中の全個体を検出できるという精度保証ではありません。
