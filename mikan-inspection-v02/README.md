# MIKAN LAB v0.2

BabylonJS / Havok / YOLOv9-Tによるミカンの搬送・画像検査・ロボット選別デモです。
公開先: https://ykoba079.github.io/test_prj/mikan-inspection-v02/

リポジトリーのルートで `python -m http.server 8000` を実行し、`http://localhost:8000/mikan-inspection-v02/` を開きます。BabylonJS/Havokは `vendor/`、ONNX Runtime Webは `../yolo-camera/vendor/` を利用します。`.mjs` をJavaScriptとして配信するHTTPサーバーが必要です。外部CDN接続は不要です。

## 箱と操作

- 箱へ入ったミカンは時間経過で削除しません。深くした半透明の箱に物理ボディを持ったまま残ります。
- 「箱を空にする」で回収済みだけを削除します。「リセット」はライン・箱・履歴をすべて初期化します。
- 検出方式・信頼度の変更時はラインと追跡を初期化し、箱の中身を保持します。
- ライン上の上限14個に箱の中身を含めません。長時間運転では物理ボディが増えるため適宜箱を空にしてください。
- 初期ローラー速度は8 rad/s、投入間隔は8秒です。ローラー速度は従来値へ戻しています。どちらも変更できます。速度を上げると取り逃がしが増えることがあります。
- 起動・設定変更時の初期3個は、正常・カビ・傷の動作確認用です。不良面を上向きに投入します。自動投入・追加投入は従来どおりランダムな面、「裏面にカビ」は裏向きです。アームの制御が正解姿勢を参照することはありません。
- 未判定回収は初期状態では無効です。画像で不良が確定した対象にアームを使います。未判定回収を有効にすると、未判定の対象も青い箱へ回収します。
- ライン終端へ到達したミカンは緑の箱へ落下します。合格判定を保証するものではありません。「未判定通過」「取り逃がし」を別に表示します。

## カメラ・検出・追跡

真上Aと左右45度の斜めB/Cから640×480画像を取得します。撮影範囲はx=-1.2〜3.6、把持区間はx=1.55〜3.25です。Aは毎回、B/Cは交互に撮影し、2つのWeb Workerで並列推論します。初回推論の準備は起動時に行います。推論中もHavok・描画・搬送・アームは動き続けます。遅い端末では古い画像による把持を見送ります。

モデルは `mikan`（果実全体）、`mold`、`damage` を検出します。不良部分の中心が果実枠内にあり、その60%以上が果実枠と重なる場合に関連付けます。果実枠は信頼度65%以上に加え、サイズ・形・画像内の果皮色の支持率20%以上を確認します。真上の位置更新は、果皮・青緑色の画素範囲が想定直径の幅85%・高さ70%以上残る場合に限定し、その中心で位置を補正します。色は背景の誤検出除去と位置補助に使い、カビ・傷の分類はYOLOが行います。不良部分の閾値は画面のスライダーで指定します。

位置・速度・追跡IDはAの画像検出だけから作ります。B/Cは一意に対応した果実へ不良の証拠を追加し、位置や速度を上書きしません。Aで隠れた対象の存在を補助確認する場合も、位置推定には混ぜません。別々の撮影2回、または3回以上追跡した果実で信頼度95%以上の不良を1回検出すると確定し、その後隠れても記憶します。同時刻の複数カメラを2回とは数えません。

直近3回までの位置を回帰して速度と誤差を推定します。少なくとも3回の位置観測と安定した推定が必要です。新しい画像に対象がない、対応が曖昧、画像が古い、位置予測の誤差が大きい場合は把持を始めません。

## ロボットと物理

アームは固定長の上腕2.0・前腕1.9、台座(3,0.9,2.1)、工具オフセット0.22です。リンクは伸縮せず、逆運動学と関節速度・加速度制限で動きます。台座±160度、肩-20〜135度、肘12〜150度。最大速度115/85/115度毎秒、最大加速度250/200/260度毎秒平方です。

待機位置を把持区間へ近づけ、不良が確定した対象へ早めに上方から準備します。実際と同じ関節制御を使い、加速・減速・位置合わせを含む到着時間を計算します。下降中も新しい画像の位置予測へ追従し、工具が届いたら追従しながら指を閉じます。工具と画像上で重なり、輪郭が十分残っていない果実枠は位置更新に使いません。移動する対象を掴む際に、関節速度がゼロになるまで待つ条件は使いません。開始には撮影から1.3秒以内の観測が必要です。4本指の遮蔽に対応し、下降・閉動作中は誤差の条件を満たす場合に限り最大4秒まで直近の画像から予測します。これを超える、または予測誤差が大きい場合は退避して再確認します。搬送や他の処理は停止しません。

`tracking.js` と `pick-planning.js` は画像由来の観測だけを受け取ります。生成時の果実ID・正解種別・実位置・姿勢を使って目標を補正しません。把持判定は `gripper-physics.js` のHavok接触イベントと実際の持ち上がりを使います。以前の「工具から横0.3・高さ0.24以内なら掴めた」という距離判定は撤去しました。

グリッパーは十字方向へ開閉する4本指です。各指はDYNAMICの剛体で、滑り止めパッドと下側の爪を複合形状にしています。工具のANIMATEDボディに[6自由度制約](https://doc.babylonjs.com/features/featuresDeepDive/physics/constraints/)で取り付け、半径方向だけ可動にし、位置モーターの最大力を各4に制限します。接触で指の移動が妨げられた場合は、目標位置に強制配置せずHavokの反力で止まります。開いた指の中心間隔は1.60、閉じる目標は0.76、パッド摩擦係数は1.2です。数値はシーン内の単位です。

指の接触を検知したら、その工具位置で閉じ続けます。接触後も不確かな画像予測を追いかけて果実を押し出す動作を避けています。対向する指の接触が0.12秒以上続くと、少し持ち上げて確認します。果実が0.12以上持ち上がり、2本以上の指の支持が残って初めて把持を確定します。運搬中も果実は同じDYNAMICボディのままで、重力・接触・摩擦を計算します。果実を工具へ固定する制約、座標の書き換え、親子付けは行いません。確認後は爪1本で支えられている場合も接触を監視し、全指の支持が0.35秒以上失われたら滑落として扱って指を開きます。開放時も物理ボディを作り直さず、そのまま重力で落下させます。果実の変形・潰れ・皮の破損は扱わない剛体モデルです。

Havokの固定軸ローラーをANIMATED、凸形状のミカンをDYNAMICとして計算します。果実へ前進速度や回転速度を直接与えず、接触と摩擦で搬送・回転させます。重力9.81、質量0.18、反発0.02、サブステップ1/120秒です。モーター停止は慣性を残し、一時停止は物理と追跡時計を止めます。現状のローラーでは姿勢が安定して裏面が十分に回ってこない場合があります。上側の接触ローラーも試しましたが、滞留・追跡の取り違えが増えたため公開版には含めていません。

JSON出力には観測・判定・把持試行・中止理由・接触した指・接触インパルス・持ち上がった量・関節制限・箱内個数・設定を含めます。画像追跡IDと生成時IDの対応表は作りません。

## モデルと限界

`models/quality-640/` は合成画像50枚（学習35・検証8・旧テスト7）から学習したYOLOv9-Tです。モデル選択後の新規静止画33枚では、IoU 0.5・信頼度0.25でカビ9/10、傷10/10でした。カビの見逃しと余分な検出が各1件、果実の余分な検出1件がありました。これは回転動画の精度ではありません。今回の制御修正でモデルの再学習は行っていません。

回転中に不良面が十分見えない、撮影間隔の間に通過する、モデルが見逃す場合があります。正常果実のヘタの誤検出も残ります。制御の修正だけで誤検出・見逃しをすべて解消するものではありません。実運転のカメラ画像と回転中の難しい面を追加学習し、動画単位で検証する必要があります。

YOLOから色解析への自動切替はありません。色解析は画面で選択するか `?detector=color` で起動します。初期化失敗時は静止プレビューとエラーを表示します。果皮・カビ・傷は手続き生成した教材用表現です。青緑色のカビは[伊藤農園の写真](https://www.ito-noen.com/dictionary/tips/826/)を参考にしています。モデルの由来・ライセンスは同梱ファイルを参照してください。

## 検証

- `test-arm.cjs`: IK/FK、固定リンク、速度・加速度・可動域。
- `test-tracking.cjs`: 画像ID、カメラ統合、別撮影の証拠、補助カメラが位置を変えないこと。
- `test-observation.cjs`: 果実候補の支持、背景・部分枠の除外。
- `test-intercept.cjs`: 移動予測、到着時刻、古い観測・不安定な観測の拒否。
- `test-gripper.cjs`: 4本指の物理モーターと接触、動的果実の持ち上げ・旋回・重力による開放、果実への固定がないこと、片側1本だけの接触を拒否すること。
- `test-image-control.cjs`: 実際のYOLO画像からHavok把持・開放・復帰、全段階のリンク長、確認後の強制開放による滑落、箱の保持・削除・上限、空ライン、誤った座標での空振り、搬送継続、JSON、モバイル。`--color` でも実行可能。
- `test-flow.cjs`: 4 rad/sで不良面が見える条件を固定し、移動するカビ・傷を画像検出して追従把持・箱へ開放。通常は両ケースの回収を要求します。`--report-only` は取り逃がしを含めて結果と理由を表示する評価用です。4本指の物理把持では空振り・滑落が残り、この流動試験は失敗する場合があります。初期速度8 rad/sでの成功率や、回転中の全面検査を保証する試験ではありません。
- `test-yolo-browser.cjs`: カビ・傷の実画像検出、推論中の描画継続、方式変更、読込失敗。
- `test-browser.cjs`: Havok接触・摩擦・回転・停止・リセット。
- `test-startup.cjs`: WASM遅延・失敗時の表示。

`node mikan-inspection-v02/<テスト名>` で実行します。ブラウザーテストはEdge/Playwrightを使います。負荷干渉を避けるため順番に実行します。公開先には `MIKAN_TEST_URL` を指定します。静止した不良面を向ける接続試験の成功は、自然な回転中の全個体を検出できるという保証ではありません。
