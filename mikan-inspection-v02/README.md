# MIKAN LAB V0.2：回転・多視点検査

YOLO学習以外の検査ラインを先行実装した版です。2026-10-05。サンプル一覧にはV0.2のみを掲載し、V0.1へのナビゲーションは撤去しています。旧版のファイルは保管用に残しています。

## 起動と公開URL

リポジトリーのルートで `python -m http.server 8000` を実行し、http://localhost:8000/mikan-inspection-v02/ を開きます。

GitHub Pagesの公開先： https://ykoba079.github.io/test_prj/mikan-inspection-v02/

BabylonJSとHavok（JavaScript / WASM）を公式CDNから取得するため、インターネット接続が必要です。取得に失敗した場合は初期化エラーを表示し、制御アニメーションへの自動切替は行いません。

## 2026-10-08：Havokによるローラー搬送

従来のミカン位置・回転角の直接更新を廃止しました。固定軸のローラーはANIMATEDボディの円柱とし、モーター相当の角速度を与えます。ミカンは扁球の凸包を形状とするDYNAMICボディです。重力・接触・摩擦・慣性・果実同士の衝突によって移動と回転が決まります。搬送中のミカンには並進速度、角速度、前進の力を直接与えていません。

物理サブステップは1/120秒、果実質量は0.18、重力は9.81、反発は0.02です。寸法はデモのワールド単位で、実機の寸法・材料・実測運動に合わせた校正は行っていません。皮の変形は扱わない剛体モデルです。

投入は入口が空いたときに行い、重力でローラー上に落とします。側面レールも物理ボディで、横方向の転がりを制限します。落下・ライン外への逸脱は別カウントとして記録します。

選別中はローラーモーターを止めますが、他の果実は慣性で動けます。アームが把持した果実だけ物理ボディを外し、従来の制御アニメーションで箱へ移します。

## この版でできること

- モーター駆動ローラーとの接触・摩擦による搬送と果実の回転。
- ローラー角速度、ミカンの摩擦係数、不良投入率の変更。
- モーター停止（物理演算は継続）と一時停止（物理演算も停止）。
- ミカンの速度・角速度・接触イベント数と落下数の表示。
- 表面に固定した不規則なカビ・擦り傷、皮の細かな模様と凹凸。
- 真上 / 斜め上の2台のカメラで640×320のレンダー画像を取得。
- 両画像を色・連結領域で解析し、ミカン位置と見えている不良を検出。
- 画像座標を果実中心の高さの平面へ逆投影し、撮影時の個体位置と対応付け。
- 同じ個体の複数フレームの判定を統合。2つの別フレームで不良を検出すると確定し、その後隠れても保持。
- 観測方向とフレーム数による、良品 / 不良 / 未判定の区別。
- 不良は赤い箱、未判定は青い箱へアームで移動。良品は直進。排除中はモーターを待機させます。
- 個体別履歴の表示とJSONダウンロード（最新80個体まで、画面は最新14個体）。
- 良品、カビ、傷、裏面カビの手動投入。自動投入も停止できます。

## 摩擦・モーターの比較

1. 自動投入をオフにし、リセットします。
2. 摩擦係数を0にして「良品を投入」。ローラーは回転してもミカンはほぼその場に残ります。0の比較ではローラー側の摩擦も0にしています。
3. 摩擦を0.7に戻し、リセットして「裏面にカビを投入」。接触によって進みながら回転し、底面カビが見える向きになると検査画像から検出されます。
4. 「モーター停止」でローラーを止めても、ミカンには慣性・重力が作用し続けます。
5. 「一時停止」では位置と姿勢も停止します。再開するとその時点の状態から物理演算を再開します。

果実の回転速度と搬送速度を別々に指定する旧コントロールは撤去しました。物理的な回転が十分な観測方向を得られなかった場合は、検査区間出口で未判定として青い箱へ隔離します。

## 判定の意味と制限

YOLO・ONNX推論はこの版で使用していません。生成時の不良種別は外観作成のみに使い、画像検出・選別判定に渡していません。

皮・カビ・傷は手続き生成した教材用表現で、実物の写真を再現したものではありません。色閾値の結果はAIの信頼度ではありません。実物の品質判定には専用モデルと評価が必要です。

観測方向は、撮影時のカメラ視線を果実の局所座標に変換し、球面上の12方向のうち最も近い方向を記録します。同じ撮影時点の2カメラは、観測方向は各々記録し、フレーム数と不良確認回数は1回として数えます。

「観測十分」の基準は12フレーム以上・8方向以上です。これはデモの判定ルールであり、表面の検査済み面積・全面検査・実物の良品保証を意味しません。基準を満たしても不良を見逃す可能性があります。

ID対応付けは、撮影時の既知の3D個体位置との最近傍照合です。実画像だけを使った追跡ではありません。入口の空きを確認して投入しますが、物理演算で果実同士が接触・重なって見える場合があります。

ローラー駆動と果実の運動はHavokで計算します。アーム、逆運動学、実機制御は物理化していません。二軸回転を直接指定する機能も撤去しています。

## YOLO導入に向けた接続箇所

`vision.js` の検出器インターフェースは `detect(ImageData)` → `[{ x0, y0, x1, y1, defects: ['mold', 'damage'] }]` です。アーム・個体履歴・観測方向は検出器と分離されています。

次段階では、ミカン全体 (`mikan`) と不良部分 (`mold`, `damage`) を検出するモデルを学習し、不良部分をミカン枠に対応付けてこの形式へ変換します。V0.1の `good/mold/damage` 全体枠方式のモデルとはラベル設計が異なります。

## 検証

`node mikan-inspection-v02/test-browser.cjs` で、実際のEdge / WebGL描画に対して以下を確認します。Playwrightのインストールパスは環境に合わせて変更してください。

- 摩擦0ではほぼ搬送されず、摩擦ありでは接触により前進・回転すること。
- ローラーはANIMATED、果実はDYNAMICとして計算されること。
- 物理的な回転により底面カビが画像で検出されること。
- カビ・傷のアーム排除、観測十分な良品の通過、観測不足個体の隔離。
- 一時停止で位置・姿勢・観測フレームが固定され、モーター停止では物理演算が継続すること。
- リセットで果実の物理ボディを解放し、ボディ数が初期値に戻ること。
- 履歴JSON、スマホ幅の表示、JavaScriptエラーがないこと。

公開先の検証には `MIKAN_TEST_URL` 環境変数を設定します。

物理APIの公式資料：[Physics V2のボディ・形状・摩擦](https://github.com/BabylonJS/Documentation/blob/master/content/features/featuresDeepDive/physics/v2/rigidBodies.md)。
