現在動いているサーバーでは以下を開いてください。

サーバーが止まっている場合、このフォルダーで次を実行します。その場合はURLの `/webgpu-csv-dashboard` を除いて開きます。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

WebGPU対応のChrome / Edgeなどで開いてください。HTTPS / localhostで利用します。GPU利用不可、バッファ上限超過、割当失敗時にはCPU Workerへ切替します。

## 操作

最初は全国・全年・全タグ・明細の合計を表示します。

- 全国地図から都道府県をクリックすると、その地域の市町村タイルを表示。
- 市町村タイルをクリックするとその市町村に絞り込み。「県全体」「全国へ戻る」で戻れます。
- 年の初期値は「すべて」。プルダウンで絞り込めます。
- 右側にタグ別の値1・値2の合計を棒グラフと表で表示。表示中のタグの最大合計を100%とする、値1・値2共通のスケールです。割合も併記します。模擬データはタグ間の合計が近いため、値1の棒は似た長さになります。
- 「CPU / GPU を5回比較」でウォームアップ後の5回中央値、CPU÷GPUの倍率、全地域×タグの結果一致を表示。

地図はホイールでマウス位置を中心に1〜40倍まで拡大・縮小し、ドラッグで移動できます。＋／−と表示リセットのボタンも利用可能。年・タグ変更では表示位置を保持し、都道府県変更でその地域を表示します。ドラッグ後のクリックは抑止します。

全国地図は地球地図日本 / Data of Japan の47都道府県境界を表示用に簡略化したSVGです。都道府県を選ぶと輪郭を拡大します。一部離島は表示範囲外。既存CSVは6都道府県のデータで、残りはデータなし。市町村は架空名なのでボタンで選択します。地図の出典と利用条件は MAP_SOURCE.md を参照してください。

## データを生成せずに画面を修正

- `index.html`: 画面、Worker、GPU shader。
- `sample-million.csv`: 既存の100万明細＋108中間集計を一度切り出した固定データ（約47.4 MiB）。
- `sample.csv`: 軽量の5行データ。
- `dashboard-million.html`: 以前のURLからの移動用。

Workerが同じフォルダーのCSVをfetchします。画面修正ではindex.htmlだけを編集し、CSVは触りません。リロード時にはCSV解析とGPU転送が必要ですが、データ生成はありません。「既存の100万件CSVを再読込」も生成せず既存ファイルを読みます。ブラウザキャッシュはサーバーの設定に従います。

新しいデータが必要なときだけ以下を明示的に実行します。既存ファイルは --force がなければ上書きしません。

```powershell
python build_sample.py --rows 1000000 --output sample-million.csv --force
```

手元のCSVもファイル選択で読み込めます。データはローカル処理し、サーバーへのアップロードはしません。

## 入力仕様

```csv
都道府県,市町村,年,データ値1,データ値2,タグ,行種別
東京都,千代田区,2024,100,20,産業,明細
東京都,新宿区,2024,200,30,産業,明細
東京都,,2024,300,50,産業,中間集計
```

必須ヘッダーは上記7列。年は4桁。値は非負32bit整数（0〜4,294,967,295）。欠損・小数・負数は拒否します。引用符内カンマ・改行、二重引用符、UTF-8 BOMに対応。タグは単一カテゴリ。

中間集計は明細に加算せず別表示します。中間集計の粒度が重なれば、その別表示でも二重計上になります。同一粒度の重複しない小計を用意するか、実運用では集計レベルとカバレッジを追加してください。模擬データは都道府県×年×タグの108小計。市町村空欄の小計は市町村指定時に対象外。

## GPUとCPUの比較条件

CPUもGPUも全行を走査し、同じフィルターと地域×タグの集計を計算します。GPUは256シャードへの32bit atomicAdd、CPUはWorker内で整数安全範囲のFloat64合計。入力時に各シャードの全行合計を検査し、32bit上限超過時はCPUを使用します。GPU上限に応じて行バッファとdispatchを分割し、チャンク境界は256行の倍数にします。

GPU storage bufferへ数値配列を一度転送し、条件変更時には条件だけ転送して小さな結果を読戻します。GPUバッファの配置はブラウザ・ドライバー管理で専用VRAMへの配置は保証されません。

比較は各方式1回ウォームアップ後、実行順を交互にして5回測定します。全回で全地域×タグの件数・値1・値2の一致を確認。倍率が1を超える場合はGPUが速く、1未満ならCPUが速い結果です。条件変更で測定結果はリセットします。

GPU時間はコマンド投入〜計算〜読戻し〜シャード合算を含み、CPU時間はWorker内部の集計でメッセージ往復を含みません。描画・CSV解析・初回転送は比較時間の外です。GPUが必ず速くなるわけではありません。全国でも中間集計108行を使うだけならCPUで十分速いため、比較の既定は100万明細です。

CPU配列、メイン側配列、GPU配列を保持。各数値配列は約26.7 MiB。CSV解析の行配列・文字列もあるためCPUピークメモリはそれ以上です。別CSVにしてもCSV解析はCPUで必要です。

## gzip圧縮の検証

通常のアクセスは `sample-million.csv.gz` を読み込みます。画面の「100万件データの読み込み方式」で非圧縮CSVへ切り替えられます。`?data=sample-million.csv` でも非圧縮版を開けます。

既存CSVを再生成せず、gzipレベル6で一度圧縮しました。

- 元CSV: 49,726,929 bytes
- gzip: 7,599,465 bytes
- 削減: 84.7%（元の約1/6.54）
- 展開後のCSVは元ファイルと完全一致

Workerがダウンロード済みのgzipをDecompressionStreamで展開し、UTF-8文字列に変換してCSV解析します。データ欄の「取得」はレスポンス取得からバイト読込まで、「展開・文字列化」はその後の処理時間です。取得はネットワークだけでなくブラウザキャッシュやレスポンス読込も含みます。CPU/GPU比較時間には両方含みません。

今回は圧縮効果の確認が目的で、CSV解析は従来どおり全件展開です。通信量は減りますが、展開後のCPU解析メモリとGPU配列は減りません。大規模化ではCSV解析のストリーム化を別途実装します。非対応環境では読み込み方式を非圧縮CSVに変更してください。手元の .csv.gz の選択にも対応。

再圧縮が必要な場合だけ実行してください。

```powershell
python compress_data.py --force
```

`node verify.cjs` は実際のDecompressionStreamを使ったgzip展開、元CSVとの一致、圧縮URL読み込み、集計値、破損gzip・非対応・HTTPエラーを検証します。Nodeでの展開時間はブラウザの実測値ではありません。
